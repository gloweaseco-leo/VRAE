# ADR-001（兼容草案，未获Owner G0）

## 实际基线

原 `contracts/v1/openapi.yaml`：OpenAPI3.1、version1.0.0、servers=[]，说明明确“Contract only”。原schema additionalProperties=false。六业务资源及独立health如下：

| 原路径 | 原输入/输出 | 本候选消费要求 |
| --- | --- | --- |
| POST /v1/audit-requests | AuditRequest → Accepted /202 | 租户身份、signed permission reference、同body幂等及持久outbox |
| GET /v1/audits/{audit_id} | AuditRun /200 | 原14状态、实际run_id、撤回/权限与无假百分比 |
| GET /v1/audits/{audit_id}/report | ReportVersion /200 | 不把原manifest直接当公众报告，另有受控投影 |
| POST /v1/audits/{audit_id}/review-decisions | ReviewDecision | 真实人身份及hash/当前版本，不能接受SERVICE自述 |
| POST /v1/reports/{report_id}/share-grants | ShareGrant /201 | Owner、当前view hash、收方、到期、持久撤销 |
| POST /v1/audits/{audit_id}/sales-handoffs | SalesHandoff /202 | 只表示请求；VF存储事实与独立人确认分别核验 |
| GET /v1/health | 内部health | 不等于前台可提交、可公开报告 |

现有VF `/api/leads` 是浏览器同源POST私有线索入口。字段含姓名/联系信息/网址/需求；同意版本VEYFRONT-PRIVACY-2026-10-30。先私有Blob put成功再201 `{ok,reference,message}`；缺配置/存储失败503；邮件提醒/确认是独立best-effort，不改变存储事实。该代码没有跨仓签名、持久幂等key或受信收据查询接口。same-origin检查不是服务身份认证。VF源码只读，未调用该路由。

## 候选决定

`vf-vrae-r0.1` 是独立的版本化adapter profile，不是对正式V1的隐式修改。`AuditCommand.request`保留逐字段合法的原AuditRequest，额外许可引用在候选envelope中；Accepted保留原202子对象并增加run_id/outbox事实。原JSON媒体类型下不可直接把这些envelope替换旧V1 body或response。

**G0前建议运输方式**：未来适配层使用独立候选版本/媒体类型（例如Owner批准的 `application/vnd.vrae.launch+r0.1+json`），内部委派原六资源，不启动第二任务/CRM后端。具体路由前缀或内容协商由Owner与VF/Codex3裁决；本PR没有部署路由、没有servers URL，也没有宣称原V1服务可访问。原V1 envelope/body/enum/version不改。

新增候选概念：availability、两层view、签名许可/收据、错误envelope、delivery_state、撤回后的access_state。原ErrorCode没有NOT_AVAILABLE、跨系统存储断开等错误，原OpenAPI也没有503/撤回端点；这些只在候选envelope使用R0_命名，不塞进旧ErrorCode。可对应的错误嵌入原合法ErrorCode；403、409、429等保留明确含义。

取消：原advance_run禁止REVIEW_REQUIRED等阶段写成CANCELLED。候选立即撤销访问/停止派发及回执，原允许转换时写CANCELLED，否则保留原合法状态并显示access_state=WITHDRAWN。撤回/取消API的实际路由、重试key、保留和删除协议须G0裁决；不能偷偷给旧状态机加转换。

报告：原content_hash只绑定RA-0 manifest及Finding，不绑定HTML/PDF/外部投影。候选另让Owner授权签名绑定 `{grant, view_sha256}` 并在当前grant索引保存此hash；中英A/B和引用均在签名内。它不修改原ReportVersion.hash算法，也不证明语义真实。R1若把这些投影纳入正式渲染manifest须单独兼容评审。

许可：用户勾选声明不是验证站点控制权。受信许可机构签名绑定完整AuditRequest、scope hash、许可ref、同意文本版本/hash；仍按当前SourcePolicy核对tenant/policy/host/path/expiry/revocation。签名lease属于不可变提交意图；幂等重试必须重用同一envelope。服务登录token可独立刷新；改变许可/请求正文则使用新意图，不用旧key掩盖变化。

VF：signed storage receipt要在实际durable save/readback之后形成，绑定tenant/audit/handoff/report-version/request_sha256/event_id/opaque VF ref/storage receipt hash/time。签名认证发行者与字节完整性，存储真实性依赖VF受信适配器与实际存储审计，不能靠字段outcome=STORED自证。VRAE不持联系资料，也不把本地fixture资格确认当真人商业事实。

| ID | 待裁决 | 当前安全默认 |
