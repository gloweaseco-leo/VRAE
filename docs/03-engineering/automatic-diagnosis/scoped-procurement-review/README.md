# L2 第一步：绑定产品区域的采购资料复核

本增量补齐“理解产品”中的采购资料复核基础，不代表完整 L2 已交付。遵循 [产品章程](../../../00-product/PRODUCT_CHARTER_V1.1.md)、[诊断方法论](../../../02-domain/AUDIT_METHODOLOGY_AND_RULES_V1.1.md)、[业务旅程](../../../02-domain/PRODUCT_AND_OPERATOR_JOURNEYS_V1.1.md)、[系统架构](../../../01-architecture/SYSTEM_AND_APPLICATION_V1.1.md)及[数据架构](../../../01-architecture/DATA_ARCHITECTURE_V1.1.md)。五维、16 条原规则及正式报告审核边界不变。

## 行为

新自动任务保存 `l2-industrial-1.0.6`，沿用 `ra2b6-1.0.5` 原始规则及证据区域。在已采集的 INFO-01 引用上，生成 `procurement_review`：产品名称、供方明确型号、原字段和值、引用位置、配置候选、复核组状态和下一步。每条资料必须来自同一产品区域；名称不等于已验证 SKU。

配置复用现有泵、阀字段，并增加砂轮采购资料候选。行业选择依据供方原文，冲突或未识别时保留未解析状态。原文字段仍可复核，不强套行业要求。复核组是可版本化的检查清单，不能解释为所有该类商品必须具备的字段。

状态区分 `OBSERVED`、`NOT_OBSERVED_IN_CAPTURE`、`AMBIGUOUS`。未观察到不等于网站缺失；不同记录先核对型号、条件和版本。支持的单值单位采用既有精确换算；范围、复合尺寸、粒度代码保留原文，不伪造数值、库存、交期、真实性或工程适配。原有敏感信息及注入过滤仍适用。

只处理已有采集证据，最多交付 8 张卡，并提供覆盖数量及截断标志。仍受已有页面上限和采集预算约束；不增加网页访问、模型调用或客户操作。旧版本按原版本重放，不回填或改写历史结果。

## VF 接入

服务通过 `deterministic_diagnosis.procurement_review` 和 `customer_presentation.procurement_review` 交付同一已保存扩展。参考适配器校验原始引用、访问记录、产品区域、字段和值及精确单位换算后，将 `procurementCards`、`procurementCoverage` 放入 `UNDERSTAND` 维度；AI 不可用时仍保留。

VF 团队需同步 `consumer/procurement.mjs`、`reference.mjs`、`vf-preview-adapter.d.mts`，沿用现有 `report-view.mjs` 与 `vf-preview-adapter.mjs`。页面实现及 VF 应用类型检查由 VF 团队完成，本增量未改 VF 仓库。旧 VF 消费端在同步前不会自动展示新卡片。

`isRulePass=false`、`verifiedSku=false`、`engineeringFit=UNKNOWN`、`formalHumanReview=false` 始终保留。本扩展未晋升原生规则 PASS，也不是人工批准的正式报告。Qwen 仍使用原有受控证据及费用边界，本次未扩大其输入。

## 验证及发布状态

依赖未合并的 PR #183 计算预算修复，作为其上的独立增量提交。两项均等待 Owner 验收，不合并、不部署。

`frozen-review.json` 来自历史真实采集证据的只读反事实重放，不是新受理任务或正式报告：识别 1 个砂轮候选，观察到磨料、结合剂、粒度、用途，尺寸标为本次未观察到；27 份历史结果按原版本重放，历史记录及共享模型账本未变，新增真实模型调用为 0。离线构造 AI 不可用交付数据，经 Node 参考适配器验证后仍有 1 张带来源卡片。没有使用已过期授权重新访问网站，也没有伪造新的授权交付回执。

`validation.json` 记录本次合成正反测试、隔离 PG 及静态检查。PG 使用一次性无网络实例，无生产数据或私有凭据挂载；其模型响应仅用于协议测试，不作真实 Qwen 证据。

## 后续增量及完成标准

按既有架构逐步推进，每步独立验证，已有能力先复用，以下尚未完成：

1. **买家旅程与五维统一输出**：串联产品、技术资料、应用/信任证据及联系路径，将现有原生规则、S2 候选和 AI 解释按五维交付；有证据才下判断，不把候选直接晋升确定事实。
2. **产品上下文与询盘**：区分找到联系链接、保留选中型号/资料上下文、存在真实输入障碍；本阶段不自动提交询盘。
3. **有限补证**：在现有 Guard、Worker、页面预算内补足必要 DOM、移动端、动态页面或 PDF 证据。现有 HTTP 资料不能证明遮挡、移动可用性或交互完成；没有观察到时保留 UNKNOWN。
4. **改造蓝图**：复用 Blueprint 能力，将已支持的发现关联具体改造动作、页面/模块范围、补证任务及验收条件；不生成自动报价或效果承诺。
5. **正式审核与交付**：把真实自动任务接入既有人工审核、ReportVersion 和定向交付通道；预览卡不等于正式 L1/L2 审批。
6. **真实咨询与内部交接**：以 VF 实际落库咨询收据连接既有 RebuildBrief。点击、扫码、诊断成功不能自动计为 E2；E3 必须由负责人确认。

行业扩展仍需逐个有证据的样本验证；本次通用字段保留及三个配置候选只是第一步，不宣称行业普适性或完整采购规格覆盖。
