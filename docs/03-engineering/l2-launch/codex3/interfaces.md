# Interface differences for Codex2 / G0 review

Baseline `contracts/v1/openapi.yaml` version1.0.0 is contract-only with `servers: []`. It is not evidence of a running public API. This change edits no frozen contract and binds no unmerged VF/Codex2 code. Candidate `PrivateAdapter` is callable only, with server-held original TaskClient and registered synthetic source; it never accepts a target URL, tenant credential, model choice or Worker command from a browser.

## Latest Owner VF-B clarification

Read-only alignment with [Owner #149 update](https://github.com/gloweaseco-leo/VRAE/issues/149#issuecomment-6984972191) and [C2 VF-B input](https://github.com/gloweaseco-leo/VRAE/issues/147#issuecomment-6984933016). VF PR36 is unmerged and its presentation DTO is not report authority. No VF code or preview was accessed/modified. C2 owns final fields and G0; this lane does not freeze cross-lane interfaces.

The new callable `ResumeProposal` demonstrates controlled server-issued one-use invitation → private cookie proposal → current original APP/PG task status. Only the trusted synthetic supervisor may issue an invitation for its server-held original TaskHandle; it confers no report review/release right. Opaque random values are hashed in an ephemeral map, expire after at most120s bounded by the local policy, are not accepted in query strings, and are cleared on restart/revocation. Wrong tenant, absent/malformed/replayed invitation, task ID as credential, query transport, revoked/stale cookie all return the same `RETURN_ACCESS_ENDED` refusal without disclosing task existence. Actual tests use the original live local API/PG after committed admission, not a successful mock status. Set-Cookie/response headers are proposals only: `__Host-`, HttpOnly, Secure, SameSite=Strict, Path=/, no-store, no-referrer; no HTTP listener, cookie or customer login is deployed. VF must exchange invitations in a same-origin POST body after C2 approval; never target/report grant or invitation in URLs, ordinary logs or analytics. This proposal has no persistence, durable OIDC or production readiness claim.

Required public mapping has independent task fact, publication and current access dimensions. `DRAFT_READY` is not customer completed, `partial` needs a real publishable partial view, and expired/access-ended belongs to access rather than a new AuditRun enum. Consumer must show unavailable when transport cannot establish current status; retain inquiry fallback, poll with bounded backoff (candidate2s→10s cap, no invented progress), retry admission only with the same key/body, and stop polling on authorization end. Exact codes, retry-after and quotas await C2; current original TaskClient intentionally collapses rejection details, so this adapter does not fabricate a public error taxonomy.

Future submit needs separately authorized VF service identity→tenant→normalized target/source policy, invitation and versioned consent/accepted_at; current drill accepts only pre-registered OFFLINE_SYNTHETIC input and original server APP credentials. Domain concurrency candidate1 and admission/backpressure limits need C2/C1 policy and measured scheduler work; this single-task drill does not claim tested quotas. Future FreePreDiagnosticView and ApprovedL2ReportView must be independently allowlisted and deny raw sources/pins, include truthful attempted/successful/unknown denominators and observation times, and preserve multi-observation/counterevidence/UNKNOWN. No released result before Owner release/G2 formal identity/version/share authorization. VF inquiry is a separate consent and actual VF private lead receipt, never synthetic ACK or a new VRAE customer master. SourceAccess still only L0/L1; no string substitution grants live L2 collection.
