# Interface differences for Codex2 / G0 review

Baseline `contracts/v1/openapi.yaml` version1.0.0 is contract-only with `servers: []`. It is not evidence of a running public API. This change edits no frozen contract and binds no unmerged VF/Codex2 code. Candidate `PrivateAdapter` is callable only, with server-held original TaskClient and registered synthetic source; it never accepts a target URL, tenant credential, model choice or Worker command from a browser.

| Contract / required flow | Actual accepted implementation | C2 decision required |
| --- | --- | --- |
| `POST /v1/audit-requests` 202 Accepted | Loopback RA4B consumes only source_ref, server bearer and idempotency key; original PG assigns request/run/job/event IDs | Public schema, schema_version and audit_id mapping are not frozen by this adapter. Candidate temporarily uses request_id as audit_id routing hint. Need authoritative versioned mapping, auth principal→tenant binding and conflict/error taxonomy. |
| `GET /v1/audits/{audit_id}` AuditRun | Actual path `/v1/audit-requests/{request_id}` returns original TEST_ONLY job status | Full AuditRun required fields, enum transitions, timestamps, input/rule versions, errors, expiry/cancel and ownership still need C2 mapping. Adapter status is explicitly NOT a v1 AuditRun response. |
| Business status and progress | Original PENDING/LEASED/TEST_ONLY_DONE/DEAD_LETTER have limited meaning | PENDING/LEASED/DONE alone cannot assert FETCHING/EVIDENCE_READY/DRAFT_READY. Candidate conservatively returns QUEUED plus native_job_state and no percent/report access; DEAD_LETTER maps FAILED. Full signed evidence→draft verification is a separate drill, not exposed as fake API success. |
| Idempotency / lost response | Original admission transaction returns same original IDs, different body same key409 | Specify retry scope, retention, key tenant binding, response cache semantics and async failure presentation without a second queue/database. |
| Current task/report identity | TaskHandle is routing only; signed nonce/assignment plus current PG source/authority required | Server-side session exchange, OIDC issuer/audience/JWKS/rotation/revocation and real-person directory must be agreed. No APP bearer or test signer in Next.js browser. |
| Cancel / orphan retry | Original cancel501, lease30 expiry reclaim, cap3 attempts and dead letter | Cancellation contract/state transitions and bounded remediation policy. Never turn cancel501 into CANCELLED or rerun a committed job to refresh identity. |
| Approved report / review decision | Draft generation and CONTROLLED ledger are real synthetic processing; formal_human_review=false/external_delivery=false | Exact report version/content/display hash, accountable actor, approved current decision, tenant rights, current revocation and G0/share policy must gate approved views. Historical receipt equality grants nothing. |
| Share grants / sales-handoff / VF customer entry | Contract paths exist; no public endpoints implemented by this work | VF owns CRM/customer entry; VRAE owns collection/evidence/rules/review. Need original approved report allowlist/redaction and explicit share-grant expiry/revocation; no automatic customer write or notification. |
| Health / monitoring | Local supervisor verifies API readiness, auth denial, PG version/status and committed facts; metadata only | Separate liveness/readiness/authenticated health response, backpressure, queue-age alarms, dependency timeouts, log policy and deployment transport. No unauthenticated data/status leak. |
| Backup / recovery | Stopped-writer same-cluster PG restore plus exact SQLite/version pins and durable PG-policy revocation demonstrated | Full globals/identity/secret/source-storage recovery and cross-store atomicity/PITR remain separate requirements. No old backup may revive newer revoked authority. |

G0 remains pending. Candidate counters/logs and synthetic review must never be written to VF as customer completion or human approval. Exceptions are explicit refusals; no arbitrary enum extension or empty report manufactured to satisfy a UI.
