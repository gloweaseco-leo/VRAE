## “终止后恢复”能证明什么

原会话及恢复后的会话在巡查时均有效且未撤销；原恢复记录为 used=true，符合用户已恢复的描述。
本轮没有再次使用用户提供的恢复码。后台在该时间窗没有记录采集或 AI 终止，恢复读到的是同一份已完成结果。

VF 组件 `connected-preview-form.tsx` blob `9bb986c71047120b2ea83c5abdaa23456f22cb33`
只在 accepted/running/analyzing 状态轮询；一次网络错误映射 unavailable 后会停止自动轮询。
这是代码可复核的中断路径，但不是首次请求失败原因已被证明。
该时间窗 VF Runtime Logs 返回空，VRAE 原 HTTP handler 又禁用了请求日志。
一次冻结工件 DTO 投影计时约 2.16 秒，不能据此断言触发了 VF 的 8 秒请求超时。
需由 VF 提供首次失败请求的脱敏状态码、耗时或 trace，才能区分网络、BFF、会话及上游错误；
不得把页面停止轮询等同于后台诊断失败，更不应要求客户用恢复码完成正常等待。
