# ADR-001: authorized target vertical on the original task queue

Owner instruction: issue 153 comment 6996436297. Base main 2883a1dd.

Accepted decision: remove business limits on invitation counts. Only configured
resource capacity constrains concurrent pending work. A deployment can provision
any number of tenants, subjects, target plans and invitations. The two tenants,
four hosts and four subjects in the executable lab are test data only.

The original M1 admission and signed generated reader represent TEST_ONLY
accepted synthetic references. Calling that port with an actual HTTP source
would falsely attest synthetic provenance. The versioned `target_v1` bridge
therefore admits the frozen VFSubmit into the SAME `ra4a.requests/runs/jobs`,
using nullable source_ref and an immutable per-request target binding. It reuses
the unchanged original claim function and 30-second leases, original FORCE RLS,
actual SESSION_USER and explicit authority `AUTHORIZED_TARGET_V1`. No second
queue, runtime raw-table grant, BYPASSRLS or original synthetic approval is used.
Original TEST_ONLY callers keep their original path. New function-only groups
cannot invoke old fixture admission/finish or read artifact tables.

Plans, current invitations, subject sessions, original source policy, APP origin
assignment epoch, Worker lease and immutable result bind tenant/request/run/job.
A PostgreSQL plan digest prevents later configuration edits from broadening an
admitted source. Principal or assignment mutation invalidates the origin epoch.
Shared source locks and a deferred result trigger enforce current permission
and the original lease at actual COMMIT. Restart never reassigns a task ID.

Source access remains L1 (or L0); native industrial diagnosis depth is separately
L2. The original R1A isolated_fetcher, SourceAccess, DNS recheck, pinned verified
TLS transport, Collector, EvidencePack, industrial Guard and NativeSource perform
the work. Actual loopback public-IP aliases serve controlled noncustomer sites
in an owned network-none namespace. No RecordedTransport, old capture or report
is the source of a new task. DNS/TLS/HTTP are real. Customer-network factories
remain `LIVE_CAPTURE_DISABLED`; config booleans cannot enable them.

The original NativeSource is explicitly controlled_only, and the original Ledger
forbids formal identity mode for that source and external grants in verified
mode. The frozen VF-B FreePreDiagnosticView labels its source synthetic. These
are precise remaining compatibility gates: changing a JSON label or clearing
controlled_only would be an approval bypass. This first runnable vertical uses
a separate current-PG operator review port into the unchanged original Ledger;
controlled ACK decisions remain CONTROLLED_REVIEW_SIMULATION. BFF report/review/
handoff routes remain 403. Actual verified-human publication requires a separately
reviewed source/review adapter and C2's explicit non-synthetic consumer profile.
No legal authorization or human approval is issued by this patch.

The committed artifact digest and original task tuple are the handoff pins for
C1's optional post-COMMIT explanation module. The existing Qwen Completion input
also requires an accepted post-COMMIT authority adapter; it is not forged from a
dictionary or invoked inside the capture lease. This vertical remains NO_MODEL.

Release: runnable controlled noncustomer vertical, not production readiness,
real-customer permission, formal human review, or customer report release.
