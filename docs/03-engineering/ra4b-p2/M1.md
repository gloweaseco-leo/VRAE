## 实际业务路径

原 APP 在真实 PostgreSQL COMMIT 后返回 HTTP202。新的独立低权限 Worker
领取该 request/run/job，在原30秒租约内读取获准的 SOURCE 原件，并实际执行
Collector → EvidencePack → 显式六规则 `ra2b6-1.0.0` → FindingPackage →
原版本化 DISC Guard → 私有 ReportDraft。

制造业合成输入使用既有获准原件中的 URL、状态和原始正文，通过严格 RecordedTransport
供 Collector 重新采集；未记录的路由直接拒绝。robots 原件哈希必须匹配，SourceAccess、
SafeFetcher、采集上限和 Guard 均真实执行。没有外部网站请求，也没有旧报告输出代入。
新的 snapshot/evidence ID 和采集时间来自本次合成执行；输入原件 SHA 独立绑定。

新结果的 source/report/HTML 原始字节、哈希、原生报告版本及
request/run/job/Worker/lease_seq/token_hash/到期时间/origin epoch/policy 同源关联。
`m1_commit` 与原始 `ra4b_test.finish` 在同一事务完成，原生 audit/outbox 唯一。
原始及新增 deferred COMMIT 校验均通过后，Worker 才返回报告回执。
进程在未提交阶段 SIGKILL 时，两部分一起回滚；之后按原租约规则重新领取。

`m1_results` 是这份原生 ReportDraft/Evidence 的不可变持久表示；
`report.native_report_version` 保留原领域版本 ID/content_hash。`report_sha256`
表示整个草稿字节的 SHA，不能当成领域 `content_hash`。

## 有界投影与完整证据

完整 EvidencePack、全部16项规则执行（显式六规则及其余未实现/UNKNOWN）、FindingPackage
和完整事实目录保留。正面事实按 INFO/TRUST/SEO 各取一个确定性代表；已证明的失败事实
保留，由原报告合同选取最多三个问题并记录遗漏。超过已有 Guard 容量则拒绝。

递归规范化成本；重放时从真实 Evidence/RuleExecution 重建并逐字节/哈希核对。
200 原件的17条事实全部保留，选择3条展示，另外14条标记为未展示正面事实。
`GeneratedReport.editorial_selection` 为界面提供17/3/14等计数，调用方应展示此说明。

## 提供给同一 SSR 的读取端口

```python
from vrae.application.ra4b_p2.m1.reader import JobAssignment, SignedGeneratedReader

reader = SignedGeneratedReader(
    anchor=held_trust_anchor,           # 既有受控签名发行者/JWKS
    assignments=held_job_assignments,  # JobAssignment：issuer/subject/DB role/tenant/job/expiry
    connect=fixed_reviewer_connection, # 真实低权限 PG16 会话
)
result = reader.read(bearer, tenant_id, job_id, nonce=server_held_nonce)
```

发行者、密钥、nonce、subject→DB role/job 映射及连接工厂均由服务端持有。
请求不提供 DB 身份或源码字节。签名/算法/受众/到期/撤销/nonce/重放先校验，
SQL 再检查真实 SESSION_USER、当前主体、任务授权、来源策略、原 epoch 与当前任务分配。
数据库实际为 `vrae_ra4a_p1`；没有伪装旧 B2/B5A 数据库名或修改旧身份验证器。

结果包含 `locator`（tenant/request/run/job/report/version及三类字节哈希、原生 finish_event）、
`source`、`report`、`html` 和上述投影说明。后三者仅供已经授权的私有进程/查看流程使用，
不写入日志或公开 CI。读取不返回 lease token/hash。它重放原 Guard/报告并核对存储字节哈希。
拒绝 peer、跨租户、错版本/SHA、撤权、旧 epoch、重复令牌和非 READ COMMITTED 会话。
数据库、Worker 或读取进程重启后，仍依赖真实持久结果和当前授权；签名边界重启须新密钥/nonce。

新任务分配从受控输入的 Reviewer 路由在提交事务内生成，运行角色没有原始表权限。
`m1_assignments.active` 可由受信操作员撤销；读取锁与实际撤销事务顺序有原生验证。
该端口只返回 `TEST_ONLY_GENERATED_NOT_APPROVED`，供后续 M2 内部审核/回执使用。
