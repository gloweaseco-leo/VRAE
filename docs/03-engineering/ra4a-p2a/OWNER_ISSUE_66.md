## Concrete implementation
1. New additive migration 0002 for **tenant + source-run + report/version + typed artifact** immutable byte records. Use bounded BYTEA raw payload; **server-side** SHA-256 and byte-length calculated from stored bytes, never trust a caller-provided checksum as proof. Distinguish complete RA3C report draft JSON, original HTML, evidence source manifest, retained source objects and Guard inputs as needed to **reconstruct and independently validate** the exact ReviewTarget; no partial graph that could silently validate only a digest. Respect existing 8MB source/HTML limits and RA3D 64KiB target contract, reject overlarge/incomplete sets rather than truncating. Keep correct 404 one-finding and 200 zero-finding/native-null separation.
2. Strictly private SQL access: RLS **ENABLE+FORCE**, tenant-bound composite FKs, owner/runtime roles NOBYPASSRLS, minimal GRANTs; no public SELECT on raw bytes, no unscoped migration-owner privilege leaked to runtime, no direct raw BYTEA SQL from an unassigned or foreign test role. Allow only a narrowly gated **synthetic** role/assignment read port with exact tenant/run/report/version/object refs. No actor JSON, caller-controlled GUC, token text or UI identity confer real authority.
3. Atomic content registration for accepted, independently replayed **synthetic** 404 and 200 byte graphs: hold independent accepted-main bytes/pins, perform original `EvidencePack/Guard/ReportDraft` and accepted `vrae.reviewing.build_target/validate_target` before registration; store original bytes + validated full digest and sealed manifest in **one transaction**. Duplicate same keys+same bytes is idempotent, altered bytes or different binding refused; no UPDATE/DELETE/overwrite even by fixture admin except explicit future retention design. Do not assume a row/hash authenticates an original external website or a human reviewer. The test-only fixture loader is not a production upload API.
4. Read path returns only **verified matching immutable bytes** by exact run/report/version/object/target and test assignment; recompute bytes digest, re-run D1/D2 target validation with independently held provenance. Fail closed on absent/corrupt HTML/CSS/source/Guard, cross-tenant, stale version, revoked assignment, unverified actor, 404/200 substitution, modified renderer version, extra claims or missing source objects. Do not trust stored metadata/target SHA as a self-attested oracle. No stale review/approval resurrection. No false 200 finding. Keep output PRIVATE/NOT_APPROVED.
5. Real transactional race and recovery: two independent PG connections try the same artifact/key and variant bytes; exactly one consistent commit, no partial graph or duplicate attestations. Test transaction rollback and connection death during multi-object registration; still no partial readable target. pg_dump/restore + actual volume/container restart must reproduce **original content SHA, byte length, tenant isolation, and latest-version behavior**, with independently held source bytes. Record internal private audit row/event for registration if needed, without external delivery and without altering existing P1 idempotency/lease/outbox behavior.
6. Show precise **future port contract** for RA4B authenticated human sessions, object service and reviewer transaction; this P2A never calls `approve_version`, `check_share`, or creates a native ReviewDecision, APPROVED report or ShareGrant. Production identity/review/store-service ports must default **DENY**. Never expose artifact raw bytes through internal task list/unauthenticated endpoints or customer-facing links.
