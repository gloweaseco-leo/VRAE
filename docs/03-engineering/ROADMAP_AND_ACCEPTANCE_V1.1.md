# VRAE 开发里程碑与验收总纲 V1.1

> 状态：计划基线，非执行记录。2026-11-10。
> 本轮仅完成文档迁移和重构，**未启动 RA-0、未运行合成或真实诊断、未建立部署**。

## 1. 正确开发顺序

业务与数据权限契约 → SSRF 安全采集 → 确定性证据/规则 → AI 辅助与人工审核 → 可靠队列与报告 → VEYFRONT 商业接入 → 灯塔业务价值验证 → 有限发布。

**关键原则**：先业务语义和来源完整性，后自动化和前端美观。Vey2GE 和 L2M 的开发/交付是否通过，不应阻塞 VRAE 早期的独立离线验证。

## 2. RA-0 至 RA-6

| 阶段 | 范围 | 必交付 | 退出验收（建议） |
| --- | --- | --- | --- |
| RA-0 契约冻结 | JSON Schema/OpenAPI、状态机、SourcePolicy、授权与费用门禁 | 合成样本、正反例、合同测试 | 至少 20 例（10 合法/受限/失败、10 业务流程），全部通过；**不得**创建生产客户数据 |
| RA-1 安全只读采集 | 受控抽取 L2M fetch/discovery、网络隔离、静态/动态页面抽样 | 有来源哈希的页面包、安全阻断日志 | SSRF、DNS rebinding、重定向逃逸、403、跨域、限额全部阻断；真实站只在许可下抽测 |
| RA-2 证据与规则引擎 | 五个买家任务、16 条规则、行业包、UNKNOWN | 规则版本、Evidence→Finding、人工 gold labels | 无证据不出事实结论；目标覆盖 >= 5 种有差异网站结构 |
| RA-3 AI 与审批 | 严格 schema、引用检查、费用停止线、Review & Report | 审核过的一页 L1 报告及回滚记录 | 客观事实 100% 具备可追溯证据；0 个严重虚构；失效模型不产伪报告 |
| RA-4 应用运行 | 独立 API、持久队列、Worker 恢复、DB/对象存储、身份 | 受保护工作台、任务状态、报告读取 | 重放幂等、异常恢复、权限/跨租户拒绝、取消、预览浏览器检查全部通过 |
| RA-5 商业灯塔 | 有许可的真实工业站、审核、真实沟通 | 真实成本、错误、审核反馈和客户意愿记录 | 10–15 份 L0、3–5 份 L1，真实双向业务反馈；没有商机就如实记录 |
| RA-6 有限上线 | 官网有限申请、限额、告知、运营、异常处理 | 上线审批/运维手册/监控与回滚 | 严格独立安全、法律、商务和运维签署，正式域名另行审批 |

以上验收目标需在阶段入口冻结正式采样和评价方法，不能在样本不够时宣称统计意义。

## 3. RA-0（此刻仅作计划，不执行）

需要制定明确 schema：
- AuditRequest、SourcePolicy、AuditRun、PageEvidence、Observation、Finding；
- AIInterpretation、ReportVersion、ReviewDecision、ShareGrant、SalesHandoff；
- EventEnvelope、UsageRecord、ErrorCode、IndustryPack。

需要具备两个 distinct SourcePolicy：PUBLIC_READONLY_RESEARCH（限制公开访问）与 OWNER_AUTHORIZED_DEEP（严格授权后深检）。它们不自动相互升级。

所有业务对象需 tenant_id、schema_version、idempotency_key、source/evidence reference（适用时）和清晰的写入权限。JSON Schema 是合同，不代表数据库结构已经确定。

## 4. 验收样本组织

- 合成站点：纯静态、SPA、CMS、工业设备、多 SKU 目录、移动端问题、有联系入口但无法证实送达。
- 拒绝样本：私网/回环/metadata、恶意编码 URL、跨域跳转、blocked robots、WAF/403、重复输入、无证据 AI 结论、旧审核版本失效、跨租户分享。
- 真实样本：仅在许可和来源条款允许下检查；登记企业、域名、所用网页、授权、检查时间和人工 gold labels。
- 每份样本明确期待的 PASS、FAIL_WITH_EVIDENCE、UNKNOWN、ACCESS_BLOCKED、NOT_APPLICABLE；不得伪造真实企业成交或 SEO 数据。

## 5. 高优先级系统级质量门禁

| 领域 | 不可妥协指标 |
| --- | --- |
| 采集安全 | Zero critical：SSRF、凭据外泄、私网 egress、任意跨域抓取、未经授权站点修改 |
| 数据权限 | 跨租户读写与撤权后的访问必须全部拒绝 |
| 事实与规则 | 对外每条客观断言可回到证据、页面和时间；采集失败不自动判站点质量差 |
| AI | 无证据引用或内容不相符时拒绝；费用未知或超预算不允许继续收费请求 |
| 审核 | 报告必须绑定人审版本与内容哈希，未经批准/过期/撤销不得分享 |
| 可靠性 | 持久受理、幂等重试、Worker crash 恢复、死信与成本留痕 |
| 商业 | E1 不升 E2、E2 不自动升 E3，合格商机需真实负责人确认 |
| 合规与素材 | 公开可读不等于有转载权，客户授权、隐私、保留与退出必须可执行 |

## 6. 候选量化阈值（开发试点，非已通过）

- 首期受许可网站中，代表页面包有效覆盖率目标 >= 80%（必须定义分母和“覆盖”的人工判据）。
- 有人工 gold labels 的诊断问题精确率目标 >= 90%，严重事实虚构 0。
- L1 模型单次运行建议预算上限 ¥2（需真实调用价验证），网页资源与人工成本单列。
- L1 所有对外报告 100% 审核；内测中逐项记录人工审核时间，避免把免费报告做成高成本人工业务。
- 真实商业试点可以把“至少 2–3 次有实际需求的双向对话”设为实验目标，但不宣称有保证或规模化转化率。

## 7. 开发批次建议（授权开发后才执行）

- RA-0A：Schema/SourcePolicy/状态机/角色合同 + 合成样本；
- RA-0B：负面测试及审计追踪合同；
- RA-1A：固定源 SHA 的 Python 采集最小提取与 SSRF 复核；
- RA-1B：浏览器动态只读观察和网络隔离；
- RA-2A：16 条规则、行业包与证据关联；
- RA-3A：AI Gateway 严格结构输出、引用约束、预算；
- RA-3B：人工 Review/ReportVersion/ShareGrant；
- RA-4A：DB/队列/存储/身份和可靠性闭环；
- RA-5A：真实小样本、人工审阅与有证据的商业评估；
- RA-6A：有限上线、告知/安全/运营/商业复核。

## 8. 变更与批准

每一阶段必须有当前 SHA、测试环境、源政策/模型版本、真实用量、证据路径、PASS/FAIL/BLOCKED 的独立结论。无法完成的门禁必须列明阻断，不可以用计划代替实际结果。发布到 VEYFRONT 生产需要单独批准；仓库文档写入不构成授权调用付费模型、网站研究或发送商务消息。
