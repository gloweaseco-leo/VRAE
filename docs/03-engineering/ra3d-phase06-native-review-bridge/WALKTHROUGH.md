# Operator / Reviewer 操作演示与剩余缺口

这份演练回答实际问题：“从产品想联系供应商的采购商，遇到了什么被原始字节支持的路径问题？我们能向谁承诺什么？”它没有证明制造商真实性、实际丢单、搜索排名或销售效果。没有真人耗时或商业效果研究，不能把测试数量计为成交价值。

打开本地 [index.html](index.html)，先确认顶部“真实 RA3C 合成证据重放 / 离线只读演练 / NOT APPROVED”。原 native 源自已验收 main，不是另写的 sim 标签。页面沿用 Phase 0.5 的中文工作台、键盘/手机交互，新增的是原生字段和字节查阅。

1. 选择 **404 / 一个 INQUIRE 路径问题**。观察事实保留 native 英文原句；中文可能影响、建议行动、重新验证方法全部仍是 HUMAN_REVIEW_REQUIRED。不要把“采购商可能绕行”读成实际丢单。
2. 点击“查看原始证据”。比较完整原生 source/evidence/snapshot 引用、href `/contact`、捕获时刻 `2026-11-10T12:00:00+00:00`、目标 HTTP 404 与 UTF-8 `[158,177)`。原始 body slice 是 `<a href="/contact">`；完整原文只是惰性文本，没有打开或执行第三方网站。点击返回，焦点回到问题。
3. 在下方“原生全文与逐条来源”逐条点击原文字节。除了一个问题和三条候选编辑，还有真实 INFO/SEO 来源元素；这些也只是“网站写了什么”，不证明资质或排名。完整 binding/guard/pointer 可展开，每条均能回到其实际 quote。
4. 展开完整版本/来源/内容摘要，再查看原生精确 HTML。预览保留 private / NOT APPROVED 水印和原 hash，没有把工作台标记写进报告。完成全部核对才可练习二次确认；结果仍是“未形成真实 APPROVE”。退回/拒绝可写意见，但不编辑原 capture、Guard、HTML 或白名单措辞。
5. 切换 **200 / 零问题**。原生 native_report_version=null。CTA PASS 有真实规则 citation，但没有对应 RA3B CTA binding/claim，界面明确缺失；不补造 finding。HTTP 200 不证明表单提交/邮件送达。核对 INFO/SEO 原文、实际覆盖与 UNKNOWN 后，只能模拟内部范围确认，没有报告批准按钮。
6. 刷新页面，之前核对和意见全部消失。演练不保存、外发或调用审批 API。

原生负例在离线 exporter 内实际尝试：改源字节、quote/offset、held refs/hash、scope、Guard、文字、版本、HTML 或把 0 改成问题都会明确拒绝。浏览器的拒绝视图不能替代真实租户认证，静态文件持有者仍可读取全部合成数据。

相较 Phase 0.5，本轮让 Reviewer 能准确指出“一条实际原生陈述对应哪份 held evidence、哪段原始字节、什么机器状态”，并看到同一原生版本的完整 HTML。没有重建整套审核工作台，也没有把预览投影改称生产审批合同。

仍未解决：真实身份与任务授权、服务端可信 ReviewTarget/全文侧车、不可变对象存储、原子事务/幂等/CAS、审计与故障恢复、任意人工文字编辑输入方案、Owner 分享和接收人授权。移动真机/微信、屏幕阅读器、真人理解率/耗时、真实企业与商务有效性均未测。此工作不减少后续 RA3D/RA4 的生产验收门禁；PR #48 独立 QA 和另行 Owner GO 仍必需。
