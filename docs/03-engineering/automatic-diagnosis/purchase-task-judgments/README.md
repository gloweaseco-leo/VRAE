# 采购任务判断与澄清建议准入

落实 Owner 的两个 P0 产品优先级：利用同一产品区域的已有证据回答采购任务，并减少缺乏依据的建议。本增量不改变五维、16 条原规则及正式人工审核边界；依据[产品章程](../../../00-product/PRODUCT_CHARTER_V1.1.md)、[诊断方法论](../../../02-domain/AUDIT_METHODOLOGY_AND_RULES_V1.1.md)、[业务旅程](../../../02-domain/PRODUCT_AND_OPERATOR_JOURNEYS_V1.1.md)、[系统架构](../../../01-architecture/SYSTEM_AND_APPLICATION_V1.1.md)和[数据架构](../../../01-architecture/DATA_ARCHITECTURE_V1.1.md)。

## 产品变化

新自动任务使用 `l2-industrial-1.0.7` 和采购配置 `1.1.0`。原生执行器及 FindingPackage 仍使用 1.0.5；旧任务及配置按原版本重放，不改历史工件、Evidence 或模型回执。

识别 `Size(MM)` 等有限明确别名，将已有尺寸资料计入已观察字段。复合编码仍保留原文，不自动拆成单值尺寸、解释字母含义或认定工程适配。配置之外的标签仍保留原文，不模糊匹配成必填参数。

同一产品区域的字段支撑三个采购任务：应用初筛、规格比对、选项关系澄清。每项保留原字段索引和引用索引，区分 `SOURCE_INFORMATION_AVAILABLE` 与 `UNKNOWN`。有资料也不表示采购决策已完成：买家实际要求未知，选项关系与工程适配未验证，任务不会因此成为缺陷。

`N/A`、`TBD` 等明确占位值保留为原字段观察，但不算作采购任务的可用信息，也不计入可带入询盘核对的参数。没有可用采购信息时，模型请求在调用前停止。

询盘准备复用该产品所在快照的原 CTA-02 观察。已到达联系路径时输出 `STATIC_ROUTE_RECORDED` 和可带入核对的现有字段索引；型号是否实际传递、表单可用性及送达继续未知，不提交表单。

S2 的严格技术资料规则仍按其原记录类型和适用条件运行。本次在采购任务层利用原生产品证据，不把泛化字段自动晋升为 S2 或原生规则 PASS。

## AI 建议准入

仅新版本启用 `qwen-purchase-clarification-1.5.0`；旧提示版本及读取行为保留。上下文固定采购任务摘要和版本化策略哈希，仅向已有受控来源组提供任务，不增加模型调用次数或费用权限。

新建议必须：

- 选择三个采购任务之一，并引用同一产品区域内完整的标签/值对；选项关系任务需至少两个相关字段。
- 在解释中保留一项相关来源值，不能仅用泛泛的优化措辞代替证据。原有跨区域、注入、商业推断及 Guard 校验继续执行。
- 类型固定为 `CLARIFICATION`。本次将动作、问题和核对方式限制在该任务对应的明确澄清文本中：先核对已有资料，未解决时请供方确认，不生成组合映射或工程参数。
- 同一采购任务不重复列入。按规格比对、选项澄清、应用初筛的固定复核顺序交付；这是本策略的展示次序，不是通用商业价值评分。

AI 解释仍是需要人工审阅的假设。本次没有实现任意自然语言的完整语义证明、工程选型或供应商认证。收紧后的动作是采购信息澄清建议，不能标为已确认缺陷或已批准改造方案。

新提示允许零条建议。只有绑定原工件、成功验证、真实提供商回执元数据及明确 `NO_SUPPORTED_OPPORTUNITIES` 原因同时成立，读取端才输出 `COMPLETED_NO_RECOMMENDATIONS`，保留已记录事实；失败和协议替身仍按原失败状态处理。没有可用采购任务证据时，在调用前保留证据不足状态。

金额、输入/输出上限及共享账本保持原控制；新提示增加了任务和允许动作文本，未宣称单次模型费用或延迟下降。

结构约束使用 `enum`、`const`、`minItems` 等[百炼官方结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)列出的能力；沿用原 wire schema 的 `uniqueItems` 移除和本地严格校验。文档核对及协议替身通过不代表已完成新提示的真实提供商验收。

## VF 接入与上线协调

上线前 VF 团队需同步参考消费端 `procurement.mjs`、`reference.mjs`、`buyer-review.mjs`、`vf-preview-adapter.mjs` 及类型声明：原客户端可能拒绝新的诊断/提示版本，单纯重新构建旧代码不足以完成接入。本增量未修改 VF 仓库或部署配置。

- 采购卡新增 `purchaseTasks`；理解产品维度提供同一来源绑定的任务列表。
- 询盘维度新增 `inquiryPreparation`，保留已连通路径与未验证的型号传递、提交状态。
- 五维提供 `recordedFacts`，便于呈现已有介绍正文、联系链接等子事实，同时保留原规则 UNKNOWN。
- AI `insights` 新增 `purchaseTask`、`opportunityKind`。`CLARIFICATION` 应展示为待澄清事项，不计入缺陷或评分。
- 消费端核对任务与字段引用、同页路径，以及动作与该任务的原固定文本；零建议完成状态不显示模型失败警告。

VF 页面及打印视图仍需 VF 团队落实。技术性能量化、自适应补充调查、可交互表单观察及完整改造蓝图不在本增量中。

## 验证边界

`frozen-review.json` 使用本次 PDF 对应真实留存工件，只读生成新版本的反事实结果，不是新受理诊断或正式报告。旧诊断重建完全相同；尺寸资料被识别，复合编码未被解释，三个采购任务有来源信息，询盘静态路径被保留，参考消费端保留七条 TRUST 子事实。28 份历史工件和共享账本核对不变，新增真实模型调用为零。

TRUST 的七条是原观察记录，包含重复联系入口及不同介绍片段，不代表七项独立资质或质量评分；页面可归组展示并保留所有来源。

对历史两条风险动作的检查仅验证其不符合新受控动作准入，没有修改旧回执，也不代表对旧模型重新调用或全面语义评审。协议测试中的提供商元数据形状是明确合成数据，不能作为真实 Qwen 调用证据。

`validation.json` 记录回归、类型检查及一次性无网络 PG 测试。实现独立提交，未合并、未部署，等待 Owner 验收。

慢采集测试曾在重型回归并行负载下因未采到产品页而未满足测试的采购卡断言；当时工件仍成功提交。停止并行重型测试后，以同样两秒逐页延迟独立复核通过。没有延长 30 秒租约或减少 12 秒收尾预算；慢站或资源不足时仍可能缺少产品证据，不能保证完整覆盖。
