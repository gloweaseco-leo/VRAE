## 新增响应字段如何消费

`customer_presentation.contract = vrae.diagnosis-presentation.v1` 是交付文案版本，不是新的报告权威。
它的 `is_report=false`、`formal_human_review=false`；`artifact_sha256` 绑定原结果。
`tasks[].observations[]` 提供 `rule_id`、`observation_id`、原 `result`、双语文案和 `source_pointer`。
指针只指向当前响应的 `deterministic_diagnosis`，引用仍从那一条原观察取得。

此字段仅做受控文字映射，不翻译或覆盖原 Evidence，不使用模型生成规则事实，不产生维度总分。
PASS 说明本次有限观察；UNKNOWN 说明未核实，不推出缺失。没有 AI 建议的维度仍显示规则事实。
采集尚未完成时视图不宣称已有诊断；模型阶段和费用继续读取原回执。

## 可执行消费与查询恢复参考

实现位于 `integration/authorized_targets/consumer/reference.mjs`，由 VF 团队审查、移植到其现有 BFF。
它只包含纯函数，没有 HTTP 请求、服务地址、密钥、存储或页面代码：

- `projectResult`：独立投影事实和 AI；核对原观察指针与结果，AI 不可展示时保留事实；只把已访问页作为引用。
- `readDecision`：对原任务 GET 做有限重试。临时失败最多连续重试 3 次，总错误窗口 120 秒；429 若超出窗口则停止自动查询，不提前重试。
- `retainView`：仅在原任务、原有效会话内保留已有视图；访问拒绝、任务不匹配或会话到期清除。

`consecutiveFailures` 只计算连续失败，正常 200/202 后归零；`elapsedMs` 从该轮连续读取失败开始计算，
不是整个诊断的运行时长。正常处理中继续按原间隔查询，不因已运行两分钟而重建任务。

这些函数不能代替现有传输鉴权，也不能被浏览器输入的“会话有效期”或“源 SHA”授权。
BFF 必须使用原服务响应及自己保管的会话；不得让用户选择上游服务或重新 POST 来恢复查询。
停止查询时表达“暂时无法确认任务状态”，不把它改成后台 FAILED，也不要求客户重新勾选授权重建任务。

运行独立反例：

```powershell
node --test integration/authorized_targets/consumer/reference.test.mjs
python -B scripts/verify_automatic_diagnosis.py --checks consumer
```

测试覆盖 AI 失败仍展示五维、虚假模型凭据不升级为真实分析、坏引用不采用、访问数不膨胀、
读失败有限重试、原任务保持以及撤权/会话过期不继续显示。所有模型“成功形状”均是明确标识的合成合同测试。

## 保持未知的范围

多型号表仍只提取可明确对应的首个数据行，不组合成不存在的 SKU；其他行的适用关系需补证。
产品名称或页面角色歧义会给出明确限制文案，不强取第一个 H1，也不把分类页误称为已核实产品。
企业真实性、移动端布局、搜索表现等没有新增验证，不借本次修复升级为已检查。

输出拒绝规则只处理明确反例，不代表全面语义审核；所有 AI 解释、建议和验证计划仍需正式人审。
没有可信问题时不凑满三条，不把 PASS 或 UNKNOWN 包装成改版缺陷。
