## 一、阶段使命、范围与停止线

**一句话使命：** 将已经存在的采集、规则、证据、Guard、报告、持久队列及审核工作台集成为一个 VEYFRONT 内部人员可亲自操作、可重复启动的 **L0→L1 合成网站 Beta**，用业务流程证明模块协同工作，而不是凭孤立单元测试和预封存报告宣称成功。

### 本阶段唯一业务流程

1. 内部 Operator 选择或发起**受控合成制造业网站** L0 检查；真正通过 API 创建并 COMMIT 申请、运行和队列任务，获得持久受理及可查询状态。
2. 独立 Worker 领取**该真实已提交任务**，以合成 HTML/离线受控传输执行 Collector→EvidencePack→RuleExecution（当前已实现的六项窄规则）→FindingPackage→Guard→版本化 L1 一页草稿；无法证实处显示 UNKNOWN/ACCESS_BLOCKED，不补造问题。
3. 结果与 **request_id / run_id / job_id / source_policy / 规则版本 / 报告哈希** 保持同源关联，落入真正的私有持久存储；任务完成状态不能代替报告已生成。
4. 内部 Reviewer 在**现有**受保护工作台查看该次新生成报告、证据定位和最多三个有依据的问题，对具体版本进行批准、拒绝或修订的内部审核操作，并保存可重启回读的审核决定/回执。原始证据不可随编辑被覆盖。
5. Operator/Reviewer 可再次打开已保存版本，**本地查看／导出一页中文 A4 合成样本**，区分内部审核与真实客户正式批准；没有外发、真实 ShareGrant、客户通知或对外部署。

**必须同时观察到：** 同一个任务、同一个来源、一次真实 Worker 执行、动态生成的报告、一次持久审核动作、重启后的读取。禁止把已封存 404/200 样本报告、静态 JOIN、无报告的 Worker DONE、截图或单独脚本运行冒充完整流程。

### 明确不进入本轮

- **不采集、不测试真实企业网站**（包括公开线上网站）；不用真实客户数据、联系信息、审批账号或外部接收者；不对实际客户发报告。
- 不接真实付费模型、广告、邮件、微信或生产商用接口；V1.1 L0 原本就允许零模型，L1 可先使用确定性事实与受控合成提议。
- 不开发完整 L2 深诊、L3 正式销售系统、公网匿名自助、通用 CRM、全行业自动分析或 16 条规则的全面自动化。
- 不把历史 A1 毒队列所有特殊恢复路径、已完成的三库灾备子项、额外生产级高并发指标当作**这一次干净合成任务业务闭环的前置交付**。历史未解决的问题如实保留，不能倒写成通过。

## 二、交付节奏：三次业务检查点、一个整体成果

检查点是**功能连续演进**，不是三批新的审批/报告/PR；各 Codex 的下一项工作在依赖具备时自然推进。

| 检查点 | 用户可实际完成的动作 | 代码与原生证明 | Owner 关注 |
| --- | --- | --- | --- |
| **M1 · L0 能执行** | 选合成站点、提交、看到任务和状态；Worker 不是只领取而是计算出真实证据及发现 | 真实 APP202-after-COMMIT、Worker 同源诊断、数据持久化，进程重启后仍能查找 | **能否实际发起一次诊断，并得到该任务自己的结果？** |
| **M2 · L1 能审核** | 在唯一签名 SSR 中打开 M1 新结果、查证据、选择批准/拒绝/修订、保存对应版本回执 | 原报告及 Evidence 不被改写，审核决定绑定报告版本/哈希，私有重启回读 | **人能否对新生成报告完成一次有效的内部审核？** |
| **M3 · 端到端可用** | 一次启动/停止；浏览器完整操作 L0→L1、查看/导出中文 A4、重启回读 | 同一源码 SHA，干净隔离 PG16、API、Worker、单个 SSR、404 和 200/证据不足分支；一次针对完整业务链的原生验证 | **VEYFRONT 内部人员能否照操作说明亲自复现？** |

**M1 不等待 M2 的 UI 全部完成；M2 可先独立建设真实端口适配，不能预接假结果；M3 可以提前准备启动和联调骨架，但只能在前两者的已验收接口上宣称贯通。**

## 三、三 Codex 的成果责任，而不是细节任务清单

| 执行者 | 完整负责的成果 | 并行工作和交接 |
| --- | --- | --- |
| **Codex1 · L0/诊断内核 Owner** | 真实 Worker 从已提交的合成任务生成、验证、保存版本化报告；提供当前 Worker 任务与授权 Reviewer 之间窄而可信的读写端口 | 自治选择最小新增持久结果表/类型化 Port；不强迫沿用旧测试夹具注册；输出可直接由 C2 消费的真实接口 |
| **Codex2 · L1/工作台 Owner** | 在**已有一个签名 SSR**中实现对同一实际任务报告的查看、逐项审核/修订/拒绝、版本化回执、内部 A4 查看/导出 | 复用 PR103/B3/B5/B6 既有成果，自行诊断修复实际 B5B 浏览器错误；先做好独立 UI，再以 C1 已合并读端口接真报告 |
| **Codex3 · 体验/集成 Owner** | 一个可重现启动、停止、浏览器操作的完整内部 Beta；保留真实状态及版本可回读，完整走查 404 和 200/证据不足分支 | 复用自己已写 Collector→DISC 集成，解决实际浏览器导航缺口；按已合并主干整合，不从兄弟 Draft 拷代码；历史 A1 专项留档后移出本阶段关键路径 |

Codex1/2/3 分别对 **业务结果**负责；所有人可以在已划归代码范围内自主决定实现细节，不应依赖 Owner 逐行给方法，也不能只把“提案已写完”当成开发交付。

## 四、Codex 自驾、自取、自纠的明确授权

### 自主执行（无需逐次请示）

在各自已授权的新增模块、测试和工作树内，Codex 可自主：
- 拆分内部实施步骤、设计接口适配、复用现有代码、补齐最小缺失功能；自选最小可行技术实现。
- 阅读仓库与真实源码、执行原生测试、定位根因，修正自身新代码、测试夹具和本次新增浏览器运行器，再运行**与变更相关的聚焦回归**；对一次失败不自动 STOP 等 Owner。
- 解决新模块里的数据类型、版本映射、报告条目选择、启动脚本和浏览器交互问题。16 个 Guard 输入上限不要求输出全部正向源事实：报告按 L1 至多三个有据问题，完整 Evidence/RuleExecution 仍可归档。
- 维护自己一个专属分支/工作树、合理提交增量、正常合入**已获 Owner 验收的最新 main**，在功能可交付时发起/更新原 Draft PR；使用自然 PR CI，不因日常小修复重跑全部历史灾备/浏览器矩阵。
- 记录本轮真正发生的 RED 和修复事实，修完后说明原因和再次通过的范围，不删除原测试失败记录，也不需要每次失败就发一份长篇停工申请。

### 仅在这些事项暂停相应危险动作并请 Owner 裁决

- 必须修改 V1.1 的产品目标、事实与审批含义、跨系统数据权威或取消本阶段“合成网站先闭环”边界。
- 必须扩大对外网络、真实客户数据、付费模型、真实客户分享/外发或生产发布权限。
- 必须更动已受保护旧迁移、原始角色/直接表访问、不可变证据或 Guard 的含义，或以放宽原有来源/身份检查、造假输出、削弱既有实质断言来换 PASS。
- 发现已证实的越权、凭据泄露、跨租户误读或数据损坏：立即隔离该动作、保留事实，由 Owner 决定真实风险处置。**该阻断只暂停受影响路径，不要求三个 Codex 全部停工。**
- 真实核心接口需要改变且会破坏 C1/C2/C3 其他已合并消费者：提交**一个最小接口决定**（现状、最小选项、影响、建议）给 Owner；其余不相关功能继续。

**不升级 Owner 的情况：** 普通 pytest 失败、浏览器导航超时、自己新夹具错误、代码格式问题、可在已授权新 schema 完成的数据存储接口、缺失的 UI 链接等，都应由 Codex 自诊自纠。报告以“已修复并证明”或“具体无法推进的关键阻断”为主，不写每日冗长进展。

## 五、Owner 的管理与裁决机制

Owner 是**产品方向与最终商业验收负责人、首席架构师、工程集成负责人**，不是三个 Codex 的逐行调试员。

- **方向把控**：只以 V1.1 的 L0/L1 业务目标和本阶段的合成业务流程纠偏；不再用 CI 数字或历史工作包数量替代客户可使用性。
- **接口仲裁**：一旦 Codex1 的生成结果 Port 清晰，优先固定最小接口与版本供 C2/C3 消费；明确模块所有权，禁止三人重复实现独立报告系统或审核平台。
- **集成调度**：每个独立可用成果都可优先验收合并；不必等三人同时完成，不机械反复同步同一个未变化 SHA。
- **质量裁决**：每个 PR 审查本次改动、自然 CI 及与真实业务路径直接相关的 PG16/HTTP/浏览器结果。真实核心失败不能强行报 PASS；若独立历史专项不影响此次干净合成业务路径，可明示为后续待办而不挡本次内部试用。
- **阶段复核只在必要时进行**：M1 可发起/产生真实报告，M2 可审核/回读，M3 整机亲自走通。Codex 内部小迭代无需 Owner 批准；出现跨模块合同或上述高影响边界才向 Owner 汇报。
- **避免新一轮任务泛滥**：不增加与这条业务流程无关的新 PR、ADR、专项环境、单独压测、历史证据再取证等；已有基础工程经过验收直接复用。
- **宣告口径**：本阶段可验收为“**V1.1 L0→L1 合成业务闭环 Beta**”；它不自动等同真实企业试点、所有 V1.1 功能完成、正式人审/客户分享或生产上线。真实网站验证作为**后续明确批准的独立阶段**，不进入当前 CI/门禁。

## 六、一次可操作的业务验收剧本

**准备：** 自仓库精确 SHA 按说明启动本机/隔离环境：PG16、VRAE API、诊断 Worker、唯一内部审核 SSR；打开可到达的本机浏览器 URL、使用实际隔离 Reviewer 测试凭据；不访问真实企业网站。

**正向任务：**
1. Operator 从选择器选取合成制造业网站版本 A（包含产品分类、代表产品、联系页）并发起新 L0；观察真实请求受理编号和工作状态。
2. Worker 在确切任务下生成 Evidence/RuleExecution/Finding/Guard 和带来源引用的中文一页 L1；404 路径问题可成为证据发现，200 路径不能被强凑成问题。
3. 操作员从任务池打开**新生成**版本，逐项打开源 URL、采集范围、时间与证据定位；最多三个获支持的发现及“可能影响/建议/复核方法”，不虚构业务损失。
4. Reviewer 对该具体版本采取批准/拒绝/修订的内部动作，系统存储版本绑定的审阅决定和回执。
5. 操作员重启服务，从同一任务读取版本与审核结果，查看/导出本地中文 A4 合成报告。

**负向任务：** 同样执行一个 200/证据不足样本，只展示可信正向事实、覆盖范围和 UNKNOWN；不能强制凑齐三个问题；切换源版本/撤权/换租户时不得把无权访问的旧结果当成新结果。失败显示可处理的业务状态，不默默声称成功。

**阶段退出：** 上述动作在实际浏览器+PG16/Worker 上全部真实完成、能够由第二个内部操作员照说明复现，并有与源码 SHA 绑定的最小验证记录。任何缺项直接列出，不能以模块 PASS 数量折算为百分比“可用”。**当前未执行此验收，不能提前标记完成。**
