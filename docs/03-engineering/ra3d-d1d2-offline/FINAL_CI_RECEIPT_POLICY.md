# Final-head receipt protocol

Commit all functional sources, tests, fixtures, local JUnit/raw evidence, source
freeze, limitations and this protocol BEFORE the final CI push. Re-read accepted
main; normal merge only if it advanced. No rebase, force push or schema/CI change.

After the final candidate has completed four new hosted jobs, retrieve the actual
run/jobs, current Draft PR, Git merge object, all four decoded original checkout
logs and original browser security ZIP. Audit the actual ordered parents (main,
PR head), exact frozen reviewing source hashes, every reviewing call outcome,
default full test counts and kernel/lifecycle security controls. Record all
original command logs and SHA-256; do not replace old attempts or claim that an
earlier successful SHA certifies a later source revision.

The post-CI receipt directory lives under this authorized evidence tree as
`post-ci/<final-head>/`. It is intentionally uncommitted, to keep the precise
checked Draft HEAD unchanged. A final PR comment/body supplies exact HEAD, main,
merge-ref, all job/artifact links, counts, hashes and limitations; the local ZIP
retains the full original logs/metadata/receipt. No extra commit is made after CI
solely to embed its own receipt. This is the same exact-head protocol accepted
in PR #48, now explicitly declared for D1/D2 before final CI.

JUnit from each local stage is labelled with the SHA actually executed. Final
dedicated dual-Python negative tests and hosted default full regressions must
execute the final source. Earlier local full JUnit and the first CI run remain
historical and are never relabelled as results of a later functional revision.

Keep Draft, auto-merge disabled, do not merge/deploy. Stop after final evidence
and await independent Owner acceptance. Actual human decisions, native approvals,
grants, customer access, live models and paid calls remain zero.
