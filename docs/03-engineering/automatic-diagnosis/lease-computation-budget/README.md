# 原租约内的诊断计算与提交预算

本轮处理已采集网页却无法保存报告的阻断，不改变 V1.1 定位、五维规则、HTTP 契约、诊断版本、人工审核和 VF 页面职责。

部署后的失败任务三次在约 37.3、33.6、32.3 秒才生成工件，均超过原 30 秒租约，最终 DEAD_LETTER，无持久化结果和模型调用。数据库拒绝过期提交是有效控制；修复不延长或重置租约，不恢复旧失败任务，不绕过提交校验。

## 最小修改

- 单次生产的同一不可变 EvidencePack、同一 1.0.5 evaluator 只计算一次规则执行。后续 Finding/Guard/NativeSource 验证继续把输入与该源推导结果逐项比对，不省略引用、包、声明、版本和作用域检查。
- 结果重放的 source_chain 同样在单次同步调用内复用计算，嵌套调用沿用当前范围。范围结束或异常即清理；不同包、其他版本或范围外的规则执行不共用结果，没有跨任务缓存。
- 复用内容存为独立字节，返回值为分离副本；篡改返回行不能污染验证基准。每次命中仍核验原包及期望引用，并检查不可变源字节身份。它不是权限缓存，也不颁发新任务或报告授权。
- CurrentAccess 每次 check 只加载一份最新 PG 上下文，同一次同步判断中的 policy 校验复用该上下文。后一次 check 必须重新读 PG；旧适配器保留 provider 回退。授权撤销轮询、DNS/连接/发送前检查、robots、SSRF、签名及最终提交条件保持。
- 自动任务为采集收尾、诊断/Guard、序列化和提交预留 12 秒；使用剩余租约约束采集。原六页是上限和优先目标，慢响应可提前结束并提交已取得的证据，未完成部分保留原 TIMEOUT/UNKNOWN。非自动任务沿用原 3 秒策略。
- 组件初始化耗时也计入绝对采集截止时间。原站点授权仍有效、内部短采集窗口耗尽时按 TIMEOUT 收尾，禁止继续访问但保留此前证据；实际授权撤销、过期、签名失效和最终租约仍按原控制拒绝。

不新增模型调用、客户授权步骤、队列或续租机制；不修改 VF 仓库及发布配置。

## 验证与边界

同一真实六页留存样本的离线剖析发现：一次生产执行了 15 次规则计算、495 次 HTML feed。候选减少为 1 次规则计算、33 次 HTML feed；三次 diagnose、两次行业 verify、Finding/Guard 校验仍执行。完整生产工件的规范化 SHA-256 前后相同。具体时间和重复测量见 performance.json；时间取决于宿主负载，不是线上时延承诺。

结果读取测量是不可变输入重放及五维重建的离线计算，没有绕过旧授权到期，也不冒称一次新的当前授权 GET、正式报告或真实 Qwen 验收。

真实 PG 回归在独立 network-none 数据库运行：原六页快速路径继续检查六页全部取得；慢响应模式每个页面人为延迟 2 秒，检查预算内取得的页面形成可读诊断，原租约提交校验和后续协议、同主体/跨主体正反测试继续执行。协议替身不是实际模型调用。见 pg-fast.json、pg-slow.json 和 validation.json。

范围内还测试：返回行篡改、错误包引用、不同包隔离、源字节变更、异常清理、当前授权/签名密钥/期限撤销，以及慢站保留证据后完成提交、预算不足不启动采集。

本轮未合并部署、未重新访问客户网站、未新增真实模型调用。原失败任务和历史结果保留，等待 Owner 独立验收。
